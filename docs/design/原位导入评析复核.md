# 原位导入评析复核

核对日期：2026-11-08。依据当前 main 源码及《实现可行性报告说明》。本次补充书架存储标记，不代表全平台原位方案已完成。

## 结论

总体方向成立：保留现有书籍身份，另存本机读取来源；外部文件只读，阅读资料照常同步。报告准确找到了同步覆盖路径的风险，但建议代码不能直接照搬，工期也只能作为估算。

## 核对成立的部分

- 目前原位入口仅开放给 iOS。`ios_linked_books.dart` 用本机授权表解析 `file/ios-linked-*`，普通导入仍复制原书。
- `row_sync_store.dart` 将远端书籍的 `file_path` 写回本地，并调用 `ReplacedBookFiles.record`。同内容在两台设备使用不同来源时，会覆盖本机引用键，还可能被当作文件替换处理。这是扩展前必须解决的问题。
- `syncFiles` / `syncBookFiles` 按内部目录检查原书，原位书通常因为内部文件不存在而跳过上传；应改为明确排除本机原位来源。
- 本地 HTTP 阅读入口仍接收 File。安卓 SAF 接入不只是改文件选择器，还需覆盖解析、哈希、PDF、OCR、索引和分享等读取链路。
- 现有删除同步书籍墓碑，不按云端文件缺席回收。“删除并同步云端副本”需要专门实现，不能简单删除目录。

## 需要修正的建议

1. **路径保护不能只在 apply 中保留两个字段。** 同步记录快照、身份归并、下一轮变更检测、替换回收都要一起处理，否则本机路径可能再次被上传或误判为替换。封面更新应继续同步，不能因本机封面存在就永久保留旧封面路径。
2. **有引用记录不等于文件可读。** 当前 `sync_status.dart` 已检查 iOS 引用解析和文件存在；报告建议的“isLinked 就算本地存在”反而会误报。应区分来源类型与可访问状态。
3. **OCR 不能因 Android 原位而跳过同步。** 用户要求原书之外的应同步资料全部同步。`document_reflow_sync.dart` 目前依赖源文件存在，接入 URI 时必须适配，不能用说明文字代替功能。封面也不是唯一会同步的二进制资料。
4. **单独 JSON 不是唯一方案。** 本机表或本机配置也可用，前提是明确排除云同步、备份和导出，并保证迁移与原子更新；是否新建 JSON 应结合现有存储选择。
5. **只读不只是申请读权限。** 替换、分享、释放空间、清理、删除都只能操作内部副本或临时文件。桌面即使系统允许写，也不得修改外部原书。
6. **流式读取不是所有消费者的完整答案。** PDF 随机访问、不可 seek 的 Provider、取消与资源释放均需验证；临时缓存要明确告知，不能悄悄变为永久副本。不能仅凭 URI 就断言所有鸿蒙来源都必须走同一种流通道。
7. **删除顺序需保证墓碑先持久化并传播，再清理云端资源。** 离线设备、并发上传、重试和共享资源引用都要防护。报告“本机已软删，所以其他设备不会重传”的推论不成立。
8. **删除语义尚有矛盾。** 原方案“删除记录、相关资料”，报告动作矩阵却保留笔记/时长；实施前需与已删除书籍管理的恢复/彻底删除统一，不能擅自扩大删除范围。
9. **默认打开方式不能保证静默设定。** 原方案允许无法持久授权时重新选择或复制，并非必须直接持久引用。报告对 Apple 外部打开一概不能持久化的说法缺少系统版本和授权来源验证。
10. **工期不是验证结果。** 21–31 人日依赖 Provider、平台权限和真机验收范围，不能据此保证交付时间。

## 新增：书籍存储标记

- 仅开启本机原位功能后，书架网格和列表显示“内部”或“原位”及不可访问状态；关闭后全部隐藏。原位总开关 UI 尚未上线，当前默认隐藏。
- 当前原位引用不可解析或文件不存在时显示“原位·未关联”；内部目标文件不存在时显示“内部·无文件”。不凭文件缺失断言云端一定有副本。
- 标记按本机数据生成，不新增同步字段，不修改书籍身份、笔记或进度。关闭格式标签不隐藏存储标记。
- 后续全平台来源模型落地后，标记改从统一的本机来源记录读取。当前版本仍只有 iOS 原位导入入口。

## 实施顺序

先落实本机来源与云端身份分离、迁移和双设备回归，再接各平台读取授权；随后完成重新关联、来源转换、删除任务。必须验证“同一本书 A 原位、B 内部，双向同步多轮后两端仍能阅读且笔记进度一致”。

本次为源码复核和标记修改，未进行六平台原位读取或云端删除实测。
