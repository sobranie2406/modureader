# 插件开发规范

本文件规定当前插件的入口、设置和调试方式。[运行接口](plugin-script-runtime.md)与[审核上架](plugin-trust.md)说明具体协议。

## 功能入口与设置

- 主设置入口统一命名为「插件」，使用拼图图标。进入后直接显示插件管理页，顶部是「启用插件」总开关，不再保留「实验性功能 → 管理插件」的中间层。
- 插件的管理、功能入口和设置集中在「插件」及对应插件详情中。不得把某个插件的设置单独加入应用主设置列表。
- 书籍、划词和阅读菜单可以放插件声明的操作入口。入口跟随插件的安装、启用、停用和卸载，不按插件 ID 写死在菜单里。
- 普通配置通过 manifest 的 `settings` 声明，在插件详情中呈现。密码校验、文件选择等需要原生交互的内容由宿主处理，也只能从对应插件页面进入。
- 未安装或未启用插件时，不显示它的入口或设置。任务开始前及异步操作返回后都要复查插件状态；停用、卸载或重新加载后，旧任务不得继续操作。

## 书籍菜单动作

`bookAction` 注册书籍长按菜单中的声明式操作，不运行 JavaScript。例如：

```json
{
  "kind": "bookAction",
  "schema": 1,
  "id": "hide",
  "name": {"zh-CN": "隐藏", "en": "Hide"},
  "command": "privateLibrary.hide"
}
```

该动作需要 `ui:book-action` 与 `library:private` 权限。宿主只处理用户实际选中的书籍，负责验证、保存和锁定；插件不接触 PIN、文件路径或数据库连接。

新增宿主扩展点应有对应的能力标记。旧版本不支持该能力时，应在安装前说明需要更新应用；不能仅用同一正式版本号区分不同 Beta 的接口。

## 本机开发调试

「插件 → 开发者调试」是未审核代码的明确开发例外，开关默认关闭，每次重启重新开启。普通插件安装继续执行官方审核签名校验。

总开关关闭时，正式与开发会话均停止运行。关闭前先完成所需验证，用户取消时两个会话都保持原状。

1. 导入 `.moduplugin` 或 ZIP，查看清单、文件指纹与权限，确认后加载。
2. 在实机运行贡献动作、修改本次调试配置并查看运行日志。更新包后使用重新加载，再次确认包及权限。
3. 关闭调试后取消任务、撤下菜单贡献并清理临时包、配置、信任记录与日志；已经由用户明确保存的书籍或笔记不因此删除。

调试包的 `manifest.json` 必须在压缩包根目录。可在默读源码目录使用现有打包工具：

```sh
dart run scripts/dev/pack_plugin.dart /path/to/plugin /path/to/output
```

书籍菜单和需要真实书籍绑定的笔记保存，应在实际书架或阅读划词入口测试。调试页的输入框用于检查脚本变换结果，不伪造书籍或阅读位置。

当前调试入口加载内存贡献 `scriptAction` 和 `bookAction`。混入会写入正式用户配置的 `aiSkill` 或 `selectionAction` 时，整包拒绝加载，不做部分启用。它们应先通过包校验及正式审核流程；后续需要内存配置覆盖层才能接入本机调试。

开发包与正式插件不能使用相同 ID 同时安装，停用或损坏的正式记录也不能被覆盖。调试包不进入官方目录、审核信任库、同步或备份；调试模式继续遵守沙箱、权限、超时和原生确认规则，不获得额外文件或网络权限。

运行日志记录动作、阶段、耗时和固定错误码，不记录 PIN、密钥、选中文字、书籍正文或脚本源码。

## 私密数据

私密书籍、笔记、划线、进度及关联资料只保存在本机。同步隔离依据私密标记，不依据当前是否解锁或是否正在显示。同步预览、失败重试、文件传输和数据库合并都要遵守同一规则。

已经存在的云端副本不自动删除。本机恢复副本保留完整数据，外发备份排除私密资料。保护标记、凭据和开发调试状态不进入设置备份。

关闭最后一个提供私密功能的插件或开发会话时，继续执行原生验证与停用确认，不得把真实用户的私密标记当作临时调试状态直接清空。

## 验证与上架

提交前检查未安装、启用、停用、卸载、重载、取消和后台返回等状态；同时验证普通书籍、正式插件和公开数据同步的原有行为。

正式上架必须提交源码、包、文件清单及审核记录，完成测试后签名，再把相同目录和安装包发布到 GitHub 与 Gitee。已经发布的版本不能修改文件指纹，应增加插件版本号。调试导入和提交源码均不代表审核上架。
