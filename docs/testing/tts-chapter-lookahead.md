# 锁屏跨章预读与媒体等待状态（2026-09-27）

## 问题与修改

用户反馈部分章节开头锁屏停顿、解锁后继续，播放器仍保持原状态。
代码检查发现：虽已使用脱离排版的章节读取，仍在章节边界临时解压正文；
在线合成的滚动队列只覆盖当前章节，媒体会话也没有区分等待与实际播放。
这些是可确认的等待路径，不等同于已确认用户手机的全部系统调度行为。

- 朗读开始及每次进入新章时预读后续最多三个可朗读章节的文档。
  不加载页面、字体或图片，不修改正文，也不推进游标或发布提前的阅读进度。
- 顺序音频队列可跨章节取文本，提前合成下一章标题/正文；当前章节的
  文本立即返回，不等待未就绪的预读。未加载/损坏的章节不能被越过。
- 只保留当前及后续三个章节的文档；停止/切换朗读模式清空缓存。
  失败的预读不随生产者轮询反复重试；到达该章时再重试，超时重新取文档。
- 系统与在线朗读共用等待状态。超过 300ms 才发布 buffering 和
  “正在加载语音”，避免普通快速切段闪烁。保留播放意图和暂停控制，
  不是通过伪造暂停/恢复来重启音频；用户暂停/停止优先。
- 旧会话的迟到结果不能清除新会话的等待状态。
